› 我刚洗澡时仔细想我们下一步要做什么. 我觉得
  1. 我们是一个报警平台,帮助用户解决报警. 但报警这个概念在当下只有研发才懂,而我们如果要面向企业和个人 vibe codinger, 就必须要向用户描述报警的重要
  性,并且帮助用户自动去实现报警.这要求我们的 quick start 要足够清晰,教程引导要足够明白,还要求我们可能要写一个帮助用户在项目中自动集成报警的 sdk.
 
  具体表现就是:
  1. 打开应用时,先渐入出现一个全屏的动态 logo,作为 loading 的标志,这很可爱,也很有意思.
  2. 然后识别用户是否为新用户,老用户就直接根据鉴权就进去平台了,而新用户需要登录(先用写死的账号密码,简化流程) -> 新手教程. 重点来了,这个新手教程需
  要一步一步引导用户连接github/gitlab项目,安装 sdk(这里还要选择是否已有报警),埋入 env webhook. 同时如果用户暂时没有,只是随意看看,那么我们要做一个
  演示的 demo,我们会做一个网站,网站里面有个按钮,点击就会发送报警收敛进平台,然后给用户展示报错 -> 收敛信息 -> 修复报错 -> 创建 pr 这全自动的链路,让
  用户看到我们的闪光点.
  3. 所以会发现,我们作为专注一个很小的痛点领域的应用,我们需要尽可能简化使用流程,尽可能让用户看懂我们在做什么.
