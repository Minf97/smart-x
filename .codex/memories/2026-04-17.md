# 报警手动分析与报警位置

- 目标：先打通第一步，支持手动分析报警，并在详情区展示本地仓库里定位到的报警位置。
- 改动：
  - 新增 `POST /alerts/:id/analyze`，后端会读取当前项目的本地托管仓库路径，并从 stack trace 里解析文件、行号、列号。
  - 新增 `src/server/alerts/analysis-service.ts`，负责在本地仓库里做路径匹配、读取代码片段、生成 `analysis.codeLocations`。
  - `src/server/alerts/repository.ts` 的 `updateAlertRow` 现已支持写回 `detailJson`，手动分析结果会持久化到 alert。
  - 前端新增 `AnalysisAction` 按钮，放在 footer 操作区，点击后调用 analyze 接口并更新 alerts cache。
  - `detail-content` 新增 `location.tsx`，展示“报警位置”、命中的文件行号和代码上下文。
  - 新增中英文文案：分析按钮、成功失败提示、报警位置、代码上下文。

# 报警位置改为搜索候选定位

- 目标：去掉基于 stack 的“报错位置”解析，改成“报警位置”候选定位，并支持点击打开本地文件。
- 改动：
  - `src/server/alerts/analysis-service.ts` 已重写，不再切 stack。
  - 现在会从 `title`、`message`、`sourceUrl`、`rawAlert` 中提取关键词，然后在本地仓库源码里做全局搜索和打分。
  - 搜索结果会返回 top 候选 `codeLocations`，附带命中的文件、行号、代码片段、绝对路径。
  - `shared/types/alert.ts` 的 `CodeLocation` 新增 `absolutePath`。
  - `src/components/detail-content/location.tsx` 里的位置项现在可点击，点击后用系统默认方式打开本地文件。
  - 新增文案：`openLocation`、`openLocationFailed`。
- 验证：
  - `./node_modules/.bin/biome check shared/types/alert.ts src/server/alerts/analysis-service.ts src/components/detail-content/location.tsx src/localization/i18n.ts src/server/alerts/repository.ts`
  - `./node_modules/.bin/tsc --noEmit --pretty false --skipLibCheck`
- 待办：
  - 后续可加入更强的候选排序，比如 route/component/log key 权重。
  - 如果要更快，可再补 `rg` 快速搜索作为可选 fast path。
