  - `backend/src/app.ts`

# 定位远端 sync-ack 404 并修正错误透传

- 目标：确认“刷新报警列表失败”的真实根因，并避免纯文本错误被再次包装成 `Remote request failed.`。
- 改动：
  - `src/server/alerts/remote-alert-service.ts`
    - 远端错误解析改为优先透传响应正文，兼容纯文本 `404 Not Found`。
  - `src/server/projects/remote-project-service.ts`
    - 同步收敛远端错误解析逻辑，避免项目接口也丢失原始响应。
- 结论：
  - 本地 `.env` 当前指向 `https://smart-x-theta.vercel.app`。
  - 仓库里的 `POST /projects/:projectId/alerts/sync-ack` 路由存在于 `backend/src/app.ts`，但旧提交没有这条路由。
  - 用户日志显示该地址的 `GET /projects/:projectId/alerts` 可用，而 `POST /projects/:projectId/alerts/sync-ack` 返回纯文本 `404 Not Found`，说明线上部署版本落后于当前仓库代码。
- 验证：
  - `npm run backend:check`
  - `npm run test`
- 待办：
  - 重新部署 `backend/` 到当前 Vercel 项目，或把 `ALERTS_BACKEND_BASE_URL` 切到已包含 `sync-ack` 路由的新部署地址。

# logger 增加终端颜色区分

- 目标：解决服务端日志纯白输出难读的问题，让时间、级别、作用域和附加信息在终端里更容易扫读。
- 改动：
  - `shared/logger.ts`
    - 新增 ANSI 颜色输出。
    - 时间使用暗色，`INFO/WARN/ERROR` 分别用蓝/黄/红，作用域统一用青色高亮。
    - 附加 JSON 信息使用暗色，降低视觉噪音。
    - 保留 `NO_COLOR` 开关，非 TTY 场景自动退回纯文本。
- 验证：
  - `npm run backend:check`
  - `npm run test`
- 待办：
  - 如果后续想再细化，可继续按作用域分配固定色，但当前先保持最小实现。
