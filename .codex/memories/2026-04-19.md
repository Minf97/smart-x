# 本地仓库上下文检索方案

- 目标：设计一条更靠谱的报警分析链路：先在本地仓库做确定性检索，再把命中的代码上下文喂给 AI。
- 结论：
  - 不应该让 AI 直接“盲搜全仓库”。
  - 最稳的顺序是：
    - 本地检索
    - AI 分析
    - 按 AI 选中的位置做二次上下文扩展
  - `filePath` 给 AI 用相对路径就够了；本地打开文件要用 `absolutePath`，这个字段现在类型里已经有。
- 方案：
  - Phase 1：
    - 基于 `title`、`message`、`stack`、`sourceUrl`、路由片段做本地 `rg` 检索。
    - 打分后只保留前 3 个候选。
    - 每个候选补齐：
      - `absolutePath`
      - `filePath`
      - `line`
      - `column`
      - `symbolName`
      - `snippet`
  - Phase 2：
    - 对 AI 选中的 1~2 个位置，再读取更大上下文：
      - 前后若干行
      - 所在函数 / 组件块
      - import 区域
  - Phase 3：
    - AI 只基于这些检索结果做根因、影响、修复建议。
    - 后续生成 PR 时再读取更深一层上下文。
- 待办：
  - 真正实现时优先改 `analysis-service.ts`，把“检索”和“AI 推理”彻底拆开。

# Electron 内置 Claude/Codex 可行性调研

- 目标：评估能否把 Claude Code 或 Codex 内置到 Electron 里，让它自己读取本地上下文、使用工具、技能和记忆。
- 结论：
  - Claude：能，但更适合接 `Claude Agent SDK`，不建议白标 Claude Code CLI UI。
  - Codex：能，而且官方明确支持“嵌入到你自己的产品”这条路，首推 `Codex App Server`。
  - 两者都应运行在 Electron `main` 进程或独立 worker/child process，不要跑在 renderer。
- 关键点：
  - Claude
    - Agent SDK 提供和 Claude Code 同级别的工具、agent loop、context management。
    - TypeScript SDK 自带本机 Claude Code binary。
    - 支持 MCP、sessions、skills、memory。
    - 但 Anthropic 明说：第三方产品默认不能提供 claude.ai 登录，需要走 API key。
  - Codex
    - Codex CLI 开源并本地运行。
    - OpenAI 在 2026-02-04 明说 `Codex App Server` 是首选集成方式。
    - 本地 app/IDE 的推荐模式就是：拉起平台对应 binary，当 child process，用 JSON-RPC over stdio 通信。
- 建议：
  - 如果你想最快做出来：
    - Claude 走 `Agent SDK`
    - Codex 走 `App Server`
  - 如果你想长期做成自己的“报警分析/修复平台”：
    - 仍建议你自己做一层统一 harness，把 provider 放在底层适配层，而不是 UI 直接绑死某一家。
- 待办：
  - 下一步可出一份你这个 Electron 项目的落地架构图：进程划分、IPC、sandbox、session、memory、repo context。
